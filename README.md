# sysinfo — сводка о системе для Linux / Raspberry Pi

[![build](https://github.com/paolosezart/sysinfo/actions/workflows/build.yml/badge.svg)](https://github.com/paolosezart/sysinfo/actions/workflows/build.yml)
![platform](https://img.shields.io/badge/platform-linux%20%7C%20arm64%20%7C%20armv7%20%7C%20amd64-blue)
![go](https://img.shields.io/badge/go-1.23%2B-00ADD8)
![license](https://img.shields.io/badge/license-MIT-green)

Утилита в духе Windows `systeminfo`, но заточена под Linux и Raspberry Pi 4B
(arm64). Один статический бинарник на Go, без зависимостей — просто скопируй
на плату и запусти.

## Зачем

`df -h` печатает симлинки и bind-mount'ы, `vcgencmd` выдаёт битовую маску
троттлинга, а `iw` — коды каналов. Приходится каждый раз лезть в мануалы.
`sysinfo` собирает всё в одну человекочитаемую сводку: без шума и без кодов,
которые надо расшифровывать вручную.

## Установка

Скачай готовый бинарник со страницы [Releases](../../releases):

```sh
# Raspberry Pi 4B / 5 (arm64)
curl -LO https://github.com/paolosezart/sysinfo/releases/latest/download/sysinfo-linux-arm64
chmod +x sysinfo-linux-arm64
./sysinfo-linux-arm64
```

Или собери сам (нужен Go 1.21+):

```sh
make arm64     # -> dist/sysinfo-linux-arm64
make release   # все цели + SHA256SUMS
```

## Что показывает

- **Система** — имя узла, ОС, ядро, архитектура, модель платы (device-tree),
  производитель, ревизия, серийный номер, часовой пояс, время загрузки и работы.
- **Процессор** — модель, производитель, ядра/потоки, текущая частота, а также
  минимальная и максимальная частота и губернатор (`cpufreq`).
- **ОЗУ** — ОЗУ (всего/использовано/свободно/кэш), тип и скорость памяти
  (DDR4/LPDDR4…, MT/s и пиковая пропускная способность), частота ОЗУ, swap и
  **ZRAM**: алгоритм сжатия, коэффициент, процент занятого, объём в сжатом виде
  и реально занятая в ОЗУ память.
- **Накопители** — только реальные файловые системы (`/`, `/home`, `/boot`,
  `/boot/firmware`, `/media/...`), с прогресс-баром, моделью устройства и
  классом/режимом шины SD-карты (`SDR104`, `Class 10`).
- **Сеть** — интерфейсы, IPv4/IPv6, MAC, трафик RX/TX, DNS-серверы и домены
  поиска; шлюз с MAC и вендором; для LAN: скорость линка, дуплекс, наличие
  кабеля; для Wi-Fi: SSID и BSSID точки доступа, диапазон и канал, скорость
  линка, ширина полосы, шифрование, сигнал.
- **Датчики (Raspberry Pi)** — температура, напряжения и такты `vcgencmd`,
  декодированный `get_throttled` (просадки питания/троттлинг: «сейчас» и
  «было с загрузки»), тепловые зоны, вентиляторы.
- **Дисплей** — разъёмы DRM и мониторы, разобранные из EDID: производитель,
  модель, разрешение и частота обновления, размер, серийный номер, год.
- **USB** — устройства с классом и протоколом интерфейсов (клавиатура, мышь,
  накопитель, хаб, аудио, видео), драйвером, скоростью линка и серийником.
- **Пользователи** — активные сессии: имя, тип (рабочий стол / локальный
  терминал / SSH / SSH без терминала), адрес клиента с обратным DNS, время
  входа, простой, служба или рабочий стол, терминал, номер сессии и PID.
  На старых системах данные берутся из `utmp`, на Debian 13 / systemd 257
  (где `/run/utmp` удалён) — из systemd-logind через `loginctl`.
- **Язык** — интерфейс на русском и английском, определяется по локали
  (`LANG`/`LC_ALL`), принудительно — флагами `--ru` / `--en`.
- **Базы вендоров** — имена производителей USB и MAC подтягиваются из `usb.ids`
  и IEEE OUI. Актуальные базы **вшиты в бинарник**, поэтому расшифровка
  работает сразу, без интернета и без кэша. Команды `--vendor` и `--oui`
  обновляют локальную копию, только если на сервере появилась новая версия
  (условный запрос `If-None-Match`/`If-Modified-Since`) — лишний трафик не
  тратится.
- **Оверклок / напряжение** (Raspberry Pi) — заданные в `config.txt` частоты
  CPU/GPU/ядра/памяти, напряжение (`over_voltage`), `force_turbo`, `arm_boost`
  и `temp_limit`, а также активные значения из `vcgencmd`.
- **RTC** (Raspberry Pi) — есть ли плата часов на шине I2C (DS3231/DS1307,
  PCF8563, MCP7940x), читается ли она ядром и синхронизированы ли с ней
  системные часы при загрузке.

## Сборка

```sh
make arm64     # Raspberry Pi 4/5 и другие 64-битные ARM  -> dist/sysinfo-linux-arm64
make armhf     # старые 32-битные Raspberry Pi            -> dist/sysinfo-linux-armv7
make amd64     # обычный x86-64 Linux                     -> dist/sysinfo-linux-amd64
make test      # тесты
make release   # все цели + SHA256SUMS
```

Вручную, без make:

```sh
CGO_ENABLED=0 GOOS=linux GOARCH=arm64 go build -trimpath -ldflags "-s -w" -o sysinfo .
```

Бинарник статический, зависимостей нет — просто скопируйте его на Pi:

```sh
scp dist/sysinfo-linux-arm64 pi@raspberrypi:~/
ssh pi@raspberrypi 'chmod +x sysinfo-linux-arm64 && ./sysinfo-linux-arm64'
```

## Использование

```
sysinfo                     # полная сводка (цветной вывод)
sysinfo --no-color          # без цвета
sysinfo --json              # машиночитаемый JSON (для скриптов и мониторинга)
sysinfo --cpu --ram         # только выбранные секции
sysinfo -sys -c -r -s -n -d -u   # короткие псевдонимы секций
sysinfo --ru / --en         # принудительный язык
sysinfo --demo              # пример вывода для Raspberry Pi 4B без железа
sysinfo --time              # сверить часы с интернет-временем (NTP/HTTP)
sysinfo --ssh-client        # версии SSH-клиентов из журнала (нужен LogLevel DEBUG)
sysinfo --vendor            # обновить базу USB-вендоров (usb.ids)
sysinfo --oui               # обновить базу MAC-вендоров (IEEE OUI)
sysinfo --version           # версия и сборка
sysinfo --install           # установить в /usr/local/bin/sysinfo (повысит права через sudo)
```

Секции: `--system`/`-sys`, `--cpu`/`-c`, `--ram`/`-r`, `--storage`/`-s`,
`--network`/`-n`, `--sensors`, `--display`/`-d`, `--usb`/`-u`, `--users`,
`--overclock`/`--oc`, `--rtc`.

Пример блока пользователей (`sysinfo --users`):

```
ПОЛЬЗОВАТЕЛИ (4)
  raspi  [рабочий стол]
    Время входа: 11.11.2026 20:06:11
    Простой: 8 ч 21 мин 0 с
    Рабочий стол: LXDE-pi
    Терминал: tty1
    Сессия: 1, PID 1075

  raspi  [SSH]  192.168.100.234
    Время входа: 11.11.2026 20:11:22
    Простой: 2 с
    Служба: sshd
    Терминал: pts/0
    Сессия: 3, PID 7981

  raspi  [SSH без терминала]  192.168.100.234
    Время входа: 11.11.2026 21:11:23
    Служба: sshd
    Сессия: 848, PID 85594
```

В заголовке показывается число сессий.

Графический вход (X11/Wayland) помечается как «рабочий стол» и показывает
имя рабочего окружения; это видно только через logind, из `utmp` тип сессии
не определить. Для SSH-сессий в строке «Служба» указывается владелец сессии.

«Простой» — это время с последнего обращения к терминалу (atime устройства),
та же величина, что показывает колонка IDLE в `w`. Она работает для всех
типов сессий; собственный idle-хинт logind заполняется только для
графических сессий и для tty/ssh остаётся пустым.

Сессия SSH **без терминала** — это неинтерактивное подключение: `sftp`, `scp`,
`rsync` или туннель. Все они идут без псевдотерминала, поэтому отличить их
друг от друга по этим данным нельзя, и утилита честно пишет «SSH без
терминала», а не выдумывает протокол.

### Время в блоке СИСТЕМА

`Текущее время` — местные часы и текущее смещение от UTC в скобках
(`GMT+03:00`). `Время установки` берётся из времени создания корневой
файловой системы (`statx`, поле `btime` — ext4/xfs/btrfs его пишут); если
файловая система его не хранит, используется время создания
`/etc/machine-id`, которое systemd ставит при первом запуске. Обе величины
приблизительны и показываются только когда доступны.

`Интернет-время` появляется только с флагом `--time`. Сначала опрашивается
NTP (`pool.ntp.org`, `time.google.com`), затем, если UDP закрыт, время
берётся из заголовка `Date` по HTTPS. В скобках — отклонение локальных часов
от сервера (локальные минус сервер): `+12 мс` значит, что часы спешат на
12 мс. Проверка ограничена по времени (5 с), поэтому при отсутствии сети
строка просто не появляется и вывод не задерживается.

Версия SSH-клиента (`Клиент:`) появляется только с флагом `--ssh-client` и
только если sshd пишет её в журнал. OpenSSH сообщает версию клиента на уровне
`LogLevel DEBUG` (не `INFO` и не `VERBOSE`), поэтому по умолчанию её в логах
нет. Чтобы она появилась, в `/etc/ssh/sshd_config` нужно поставить
`LogLevel DEBUG` и перезапустить sshd — иначе строка «Клиент» просто
отсутствует. Версия сопоставляется с сессией по адресу клиента.

### Raspberry Pi: config.txt, оверклок и RTC

На Raspberry Pi утилита дополнительно читает `config.txt` и показывает два
блока: **ОВЕРКЛОК / НАПРЯЖЕНИЕ** и **RTC**. Файл ищется сначала в
`/boot/firmware/config.txt` (Raspberry Pi OS Bookworm и новее), затем в
`/boot/config.txt` (старые образы). Поддерживаются условные фильтры
(`[pi4]`, `[all]`, …) и директива `include`, поэтому в вывод попадают именно
те значения, что применяются к вашей плате.

Блок **ОВЕРКЛОК / НАПРЯЖЕНИЕ** показывает заданные в `config.txt` частоты
`arm_freq` (CPU), `gpu_freq`, `core_freq` (ядро GPU) и `sdram_freq` (память),
а также `over_voltage` в виде `+N (≈X.XX В)`, `force_turbo`, `arm_boost` и
`temp_limit`. Если установлен `vcgencmd`, рядом показываются значения, которые
прошивка считает активными на данный момент (в скобках «активно N»), что
позволяет заметить расхождение между файлом и реальным режимом. Напряжение
переводится из диапазона `[-16,8]` в вольты: `0` ≈ 1.35 В, шаг 0.025 В
(`over_voltage_delta` на Pi 4/5 показывается в микровольтах).

Блок **RTC** отвечает на два вопроса: установлена ли плата часов и использует
ли её система. Сначала читается `/sys/class/rtc/rtc0` (имя драйвера, время,
флаг `hctosys` — были ли системные часы выставлены из RTC при загрузке). Затем
шины `/dev/i2c-*` опрашиваются напрямую (ioctl `I2C_RDWR`) по адресам типовых
микросхем: `0x68` — DS1307/DS3231 (модуль ZS-042), `0x51` — PCF8563,
`0x6f` — MCP7940x. Найденный чип показывается как `DS1307/DS3231 @ 0x68`.
Строка «Синхронизация» подсказывает состояние: часы синхронизированы с RTC
при загрузке; плата найдена, но `hctosys` выключен; или плата есть, но в
`config.txt` нет `dtoverlay=i2c-rtc`.

Для опроса I2C нужен доступ на чтение `/dev/i2c-*` (обычно группа `i2c`); без
него строка о плате часов показывает причину, а остальное работает как есть.
Тип и скорость ОЗУ определяются по модели платы (Pi 4 — LPDDR4-3200,
Pi 5 — LPDDR4X-4267 и т. д.); на x86 те же данные берутся из SMBIOS, если
таблицы доступны на чтение.

Переменная окружения `NO_COLOR` также отключает цвет.

## Зависимости во время работы

Ядро информации берётся напрямую из `/proc` и `/sys`, поэтому работает везде.
Дополнительные детали подтягиваются, если установлены соответствующие утилиты:

| Утилита   | Что добавляет                                   |
|-----------|-------------------------------------------------|
| `vcgencmd`| температура, напряжения, такты, `get_throttled` |
| `iw`      | SSID, канал, ширина полосы, шифрование Wi-Fi    |
| `ethtool` | скорость и дуплекс, если нет в `/sys`           |
| `resolvectl` | актуальные DNS-серверы systemd-resolved     |
| `loginctl` | список сессий на Debian 13 / systemd 257, где нет `/run/utmp` |

Если чего-то нет — секция просто деградирует, утилита не падает.

## Разработка

```sh
go vet ./...
go test ./...
```

Парсеры `/proc` и `/sys` вынесены в отдельные функции, поэтому их можно
проверять на фикстурах без реального железа — см. `sysinfo_test.go`
и `extra_test.go`.

Версия встраивается при сборке:

```sh
go build -ldflags "-X main.version=$(git describe --tags --always)"
```

`make` и CI подставляют её автоматически; без `-ldflags` значение равно `dev`.

## Кэш и базы вендоров

Локальные копии баз лежат в `$XDG_CACHE_HOME/sysinfo` (по умолчанию
`~/.cache/sysinfo`). Порядок поиска при расшифровке вендоров:

1. кэш пользователя (`~/.cache/sysinfo`);
2. системные копии дистрибутива (`/usr/share/ieee-data/oui.txt`,
   `/usr/share/misc/usb.ids` и т.п.);
3. база, вшитая в бинарник.

Последний пункт означает, что утилита показывает имена производителей
даже на машине без интернета и с пустым кэшем. Файлы обновляются командой
`sysinfo --vendor` / `sysinfo --oui`; если на сервере версия та же, загрузка
пропускается.
